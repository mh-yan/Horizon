## [DeepMind's AlphaProof Code Verifies Signal Protocol, Sparks Debate](https://deepmind.google/blog/introducing-alphaproof-code/) ⭐️ 8.0/10

Google DeepMind introduced AlphaProof Code, a multi-agent AI framework that uses proof assistants like Lean to formally verify software, and applied it to prove key security properties of libsignal, Signal's reference implementation, at the machine-code level. The announcement claims zero bugs were found in the verified library, a result that has drawn skepticism from the community. This represents a significant advance in AI-driven formal verification, potentially enabling broader application of mathematically rigorous correctness proofs to real-world production software. If scalable, it could fundamentally change how critical systems like messaging protocols and cryptographic libraries are validated, moving beyond testing to guaranteed absence of certain bugs. The framework uses multiple AI agents to translate live code into valid Lean theorems and proofs, and it operates at the machine-code level rather than on source code. However, the community notes that the verification only checks the implementation against a specification, not the correctness of the specification itself, and there are concerns about whether the theorems captured all relevant properties.

hackernews · ilreb · Nov 10, 12:11 · [Discussion](https://news.ycombinator.com/item?id=50439193)

**Background**: Formal verification uses mathematical logic to prove that a system satisfies a formal specification, unlike testing which can only sample inputs and cannot demonstrate the absence of bugs. Lean is an open-source proof assistant and programming language that enables writing machine-checkable proofs, and it has been used to verify cutting-edge mathematics. AlphaProof Code builds on this by using AI agents to automate the creation of Lean proofs for software, a traditionally labor-intensive task.

## [Chrome leads cross-vendor effort to teach coding agents modern web primitives](https://github.com/GoogleChrome/modern-web-guidance) ⭐️ 8.0/10

Google Chrome, in collaboration with Firefox, MDN, and Edge, released version 1.0 of 'modern-web-guidance', a collection of over 200 curated guides (about 1.7MB) designed to steer coding agents toward native web platform features instead of outdated JavaScript and div-based patterns. The project is distributed as an agent skill and a CLI with a built-in RAG search engine and a deterministic 'legacy-scan' tool trained on 30,000 GitHub repositories. Coding agents often default to legacy patterns like div+JS modals even when modern native APIs exist, so this cross-vendor guidance could significantly improve the quality and accessibility of AI-generated frontend code. The involvement of Firefox, MDN, and Edge signals rare multi-browser consensus on best practices, though critics worry it may entrench Chrome's influence over web standards. The package includes a RAG search that runs in about 10ms on CPU as a ~7MB pure-JS package (down from a 500MB native stack), and the legacy-scan tool achieves 92% average precision on held-out repositories. In evaluations across 200 tasks with ~1,700 Playwright/AST assertions, agents improved from 55% pass rate unguided to 92% guided.

hackernews · paulirish · Nov 10, 18:01 · [Discussion](https://news.ycombinator.com/item?id=50443812)

**Background**: Modern browsers now natively support many features that previously required JavaScript libraries or custom code, such as the CSS Custom Highlight API for styling text ranges without wrapping them in spans, the <dialog> element with showModal() for accessible modals, and the field-sizing CSS property for auto-growing textareas. However, large language models trained on older code often fail to use these native solutions, defaulting to familiar div+JS patterns. This project aims to bridge that knowledge gap by providing curated, expert-written guidance that agents can retrieve and apply.

Anthropic launched Claude Meetings, a feature that lets Claude participate in live workplace discussions by drafting plans, mapping timelines on a whiteboard, answering questions in meeting chat, and pulling data from connected work apps. The product is launching in beta for Google Meet on Team and Enterprise plans. This moves Claude from a passive chat assistant into an active participant in real-time meetings, a competitive step in the enterprise AI assistant space where Microsoft Copilot and Google Gemini are also integrating deeply into workplace workflows. It could change how teams capture decisions and assign tasks during discussions. Claude Meetings is initially limited to Google Meet on Team and Enterprise plans, with Anthropic planning to expand to additional meeting platforms in later releases. The brief excerpt does not detail how external participants or data privacy are handled.

Claude Meetings extends this by having the assistant actively participate during the meeting rather than only processing transcripts afterward.

## [Google expands TPU lineup with chips for confidential training and memory](https://techcrunch.com/2026/11/10/google-broadens-its-ai-hardware-portfolio-with-two-new-specialized-chips/) ⭐️ 7.0/10

Google announced two new specialized Tensor Processing Units (TPUs) that broaden its AI chip portfolio to cover confidential model training and increased memory capacity. The announcement, reported on November 10, 2026, signals Google's push to address more diverse AI infrastructure workloads beyond standard training and inference. This expansion matters because confidential training allows enterprises to protect sensitive data and model intellectual property during training, while higher memory capacity enables larger models and more efficient workloads. It strengthens Google's TPU ecosystem against GPU competitors and gives cloud customers more specialized options within Google Cloud. The new TPUs are purpose-built for specific use cases: one targets confidential model training, likely leveraging trusted execution environments, and the other focuses on higher memory capacity for memory-intensive AI workloads. Google has not yet disclosed detailed specifications, pricing, or availability dates.

rss · TechCrunch · Nov 10, 15:54

**Background**: Tensor Processing Units (TPUs) are custom ASICs developed by Google since 2015 to accelerate neural network workloads, supporting frameworks like TensorFlow, JAX, and PyTorch. Confidential computing protects data in use by isolating it within hardware-based trusted execution environments, and extending this to model training is a growing focus for cloud providers. Memory capacity is a critical factor for training large AI models, as it determines the size of models and batch sizes that can be handled efficiently.
