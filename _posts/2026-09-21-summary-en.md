China's Tianwen-3 aims to return no less than 500 grams of Martian samples using a dual-launch architecture in the 2028–2029 Mars window.

## [Cloudflare Python Workers reach general availability after two-year preview](https://blog.cloudflare.com/python-workers-ga/) ⭐️ 8.0/10

After a two-year beta, Cloudflare has announced that Python Workers are now generally available, making Python a first-class, fully supported language on its serverless edge platform. The runtime executes Python via Pyodide compiled to WebAssembly, and Cloudflare contributed upstream changes so HTTP clients like Requests and urllib3 can route requests directly through the JavaScript fetch API. This gives Python developers a way to deploy code to Cloudflare's global edge network without learning JavaScript or managing containers, potentially broadening the audience for serverless edge computing. It also signals growing momentum for WebAssembly as a language-agnostic runtime layer, with Pyodide becoming a standard path for running Python outside CPython's native environment. The implementation relies on Pyodide, a port of CPython to WebAssembly/Emscripten, and package support has been standardized through PEP 783 (PyEmscripten). Cold-start performance remains an open question, since WebAssembly spin-up has historically been slower than the V8 isolates used for JavaScript Workers, though Cloudflare claims isolate-based cold starts in the single-digit millisecond range.

**Background**: Cloudflare Workers is a serverless platform that runs code across a global network of edge data centers, traditionally using JavaScript and V8 isolates rather than containers. Pyodide compiles CPython to WebAssembly, allowing full Python and many C/C++/Rust extension packages to run in environments where a native Python interpreter is unavailable. WebAssembly is a portable binary instruction format that lets languages like Python execute in sandboxed runtimes such as browsers and edge platforms.

## [TypeSafe AI Unveils Jev, a 'System One' Decision Model](https://simonwillison.net/2026/Sep/21/jev/) ⭐️ 8.0/10

TypeSafe AI has unveiled Jev, the first of a new model category it calls 'System One models,' which accepts text input but returns typed probabilistic decisions — categories, yes/no answers, ratings, and confidence scores — instead of generated text. Jev is priced at $0.042 per million input tokens with output free, making it cheaper than OpenAI's GPT-5 Nano at $0.05 per million tokens. This represents a potential paradigm shift for LLM applications, since many production use cases — spam detection, labeling, ranking, and search reranking — are fundamentally classification tasks that don't need prose output. By eliminating text generation, JSON parsing, validation, and retries, decision models could make AI pipelines faster, cheaper, and more reliable for software that consumes structured results directly. Jev supports three question types: Noul (Bernoulli) yes/no questions returning a confidence between 0 and 1, choice questions returning a probability distribution over provided options, and score questions returning a float along a numeric range; questions are evaluated in parallel against a single 'state' object. A key caveat is that Jev is a black box — it returns only floating point numbers with no justification, raising concerns about hidden bias, especially in high-stakes uses like ranking job applicants.

rss · Simon Willison · Sep 21, 23:09

**Background**: Large language models conventionally take text in and produce text out, which means applications must parse and validate that output before using it. TypeSafe AI frames Jev as a 'frontier-intelligence function call: unstructured state in, typed probabilistic decisions out,' positioning it as a fast, cheap alternative for classification-style tasks. The 'System One' name references dual-process theory in psychology, where System 1 thinking is fast and intuitive, and the naming has sparked debate — designer Maggie Appleton argues 'decision models' is a clearer label.

## [US Suspends $800 De Minimis Exemption for Imports Indefinitely](https://www.personalimportation.org/advocacy) ⭐️ 7.0/10

On June 24, 2026, U.S. Customs and Border Protection published a Federal Register rule indefinitely suspending the de minimis administrative exemption for imports valued at $800 or less arriving through the international postal network. The same rule establishes a new postal informal entry process for mail shipments, with a related test allowing informal entry type 13 for shipments valued at $2,500 or less. The change removes a long-standing duty-free channel that cross-border e-commerce platforms, small sellers, and individual consumers have relied on for low-value imports. It could raise costs and add customs friction for direct-to-consumer shipments from abroad, reshaping how marketplaces like Shein, Temu, and small overseas retailers serve U.S. buyers. The new postal informal entry process requires a 10-digit HTSUS code and a tracking number, restricts who may file entry to the owner/purchaser or a licensed customs broker, and imposes bonding requirements. Postal shipments will now pay the same tariffs as commercial shipments, and the related test covers mail imports valued at $2,500 or less.

**Background**: De minimis is a legal doctrine meaning the law does not concern itself with trifling matters; in U.S. trade, it has allowed imports valued at $800 or less to enter duty-free with minimal paperwork. The Federal Register is the official daily journal of U.S. federal agency rules and notices, and the de minimis exemption has been a key pillar of cross-border e-commerce growth. This rule suspends that exemption for postal shipments and replaces it with a more formal, data-heavy entry process.

A new blog post on Hugging Face by Multiverse Computing CAI proposes framing the removal of transformer blocks in large language models as an Ising optimization problem, drawing a direct analogy to statistical physics. Rather than using heuristic importance scores, the approach treats block selection as an energy-minimization task over a spin system, where each block is a binary variable that is either kept or removed. Block pruning is one of the most practical ways to shrink large models for cheaper inference, and reframing it as a well-studied combinatorial optimization problem could yield better compression-quality trade-offs than greedy or entropy-based heuristics. If the Ising formulation scales, it may influence how researchers approach structured pruning across the model-compression ecosystem. The Ising formulation maps each transformer block to a binary spin, with pairwise interaction terms encoding how blocks depend on one another, so the solver searches for a low-energy configuration that keeps the most useful blocks. As with any Ising solver, the main caveat is the local-minima trap, where the optimizer settles on a good-but-not-optimal subset of blocks.

Structured pruning removes entire transformer blocks from an LLM to cut memory and compute, but deciding which blocks to drop is combinatorially hard because blocks interact. Physics-inspired machine learning, which borrows concepts from statistical mechanics for ML problems, is a rapidly growing research area that this work sits within.
